Software

Initialization

An application must initialize the the hardware interface before calling any of the other routines.  Initialization is performed by invoking

int ospreyEVGInit(uint32_t baseAddress);

The return value is 0 if registration succeeded and -1 otherwise.  If the block design component name is ospreyEVG the memory-mapped I/O base address to pass as the argument will be defined in the board support xparameters.h file as XPAR_OSPREYEVG_S_AXI_BASEADDR.

Status

The event generator firmware configuration is returned by

int ospreyEVGConfiguration(void);

Input Mapping

The mapping of inputs (hwInputs_a) to hardware triggers or distributed by is set by the functions
int ospreyEVGSetHwTriggerInputMap(uint32_t mapping);
int ospreyEVGSetDbusInputMap(uint32_t mapping);
where the mapping argument is a set of four bit fields specifying which input line should drive the corresponding hardware trigger or distributed bus line.  A value of 0 disables the corresponding hardware trigger or distributed bus line.  A value of 1 configures the first input line to drive the corresponding hardware trigger or distributed bus line, and so on.  The least-significant four bit field applies to the first hardware trigger or the least-significant distributed bus line.

The mapping is read back from the FPGA by the functions
uint32_t ospreyEVGGetHwTriggerInputMap(void);
uint32_t ospreyEVGGetDbusInputMap(void);

Time of Day

The time of day sent by the event generator is initialized by invoking
int ospreyEVGSetSeconds(uint32_t posixSeconds);
Once set the seconds value is incremented by each rising edge of the PPS marker.

Heartbeat Events

The rate at which heartbeat events are generated is the evgClk divided by the divisor set by invoking
int ospreyEVGSetHeartbeatDivisor(uint32_t divisor);

Timer-requested Events

The event and rate at which timer-requested events are generated  are set by invoking
int ospreyEVGSetTimerEvent(int timerIndex, int evCode);
int ospreyEVGSetTimerDivisor(int timerIndex, uint32_t divisor);
The rate is the evgClk divided by by the specified divisor.  A timerIndex value of 0 corresponds to the first timer.
Timers are controlled by invoking
int ospreyEVGSetTimerControl(int timerIndex, uint32_t control);
where the control argument consists of a series of two bit values with the least significant two bits corresponding to the first timer, the next most significant bits to the second timer and so on.  The value of each pair of bits controls its corresponding timer as described in the following table.

Value
 Description
0
 No-op (stopped timer remains stopped, active timer remains active).
1
 Stop timer.
2
 Resume stopped timer.
3 Load timer with divisor and start timer.

Attempts to (re)start a timer with an invalid or uninitialized event code or divisor are ignored.

Timer status is returned by
int ospreyEVGSetTimerControl(void);
where the return value consists of a series of two bit values with the least significant two bits corresponding to the first timer, the next most significant bits to the second timer and so on.  The most significant bit of each pair of bits is the timer status (0/1, stopped/active).  The least significant bit of each pair of bits is always 0.

Hardware-Triggered Events

The event and rate at which timer-requested events are generated  are set by invoking
int ospreyEVGSetHwTriggerEvent(int hwTriggerIndex, int edge, int evCode);
 The hwTriggerIndex specifies the hardware trigger input which will send the specified event code.  If edge is 0 the event code will be sent on the rising edge of the hardware trigger.  If edge is 1 the event code will be sent on the falling edge of the hardware trigger.
An event code of 0 results in no event being triggered by the specified input and edge.

Software-Triggered Events

An arbitrary event code is transmitted by invoking
int ospreyEVGSendSoftwareEvent(int index, int evCode);

Event Sequencer

There are up to eight event sequencers in the event generator.  Each sequencer is in one of the states shown in the following table.

Sequencer States
State Transitions
Idle
 To Armed by writing a 1 to the corresponding 'Arm' bit in the control/status register.
Armed To Idle by writing a 1 to the corresponding 'Disarm' bit in the control/status register.
To Triggered on the arrival of a software or hardware trigger.
Triggered To Idle by writing a 1 to the corresponding 'Disarm' bit in the control/status register.
To Active when no sequence is active and no higher priority sequence is in the Triggered state.  The transition to the Active state clears the 'Armed' bit in the control/status register.
Active To Idle upon detection of the 'End of Sequence' event code (255) in the pattern or when the pattern memory address pointer wraps around, or by writing a 1 to the 'Cancel' bit in the control/status register.


Event patterns are written to the sequencer RAM by first specifying the sequence to be emitted by calling
int ospreyEVGSequencerWriteCode(int bank, int address, int eventCode, uint32_t delay);
int ospreyEVGSequencerWriteDelay(int bank, int address, uint32_t delay);
where bank and address specify the location in the sequence RAM to be written and eventCode and delay specify the value to be written.  Delay values specify the number of event generator transmitter clocks (1/20th of the line rate) to pause before the corresponding event is transmitted.  With a 2.5 Gb/s line rate this corresponds to a maximum delay between events of over 34 seconds.  Delays longer than this can be obtained by chaining together multiple delays with an event code of zero.  Event codes are unsigned 8 bit values.  The end of a sequence is indicated by an entry with an event code of 255.

Sequence pattern memory contents can be read back with
int ospreyEVGSequencerReadback(int bank, int address, uint32_t *delay);
The return value is the event code.
 
Event sequencers are enabled or disabled by calling
int ospreyEVGSequencerArm(int banks);
or
int ospreyEVGSequencerDisarm(int banks);
respectively, where banks is a bitmap of which sequencer banks to arm or disarm.

Calling
int ospreyEVGSequencerSoftTrigger(int banks);
initiates a sequence where banks is a bitmap of which sequencer banks to trigger.  If more than one bank is triggered then the highest priority enabled bank will be emitted.  The least significant bit of banks (0x1) corresponds to the first, lowest-priority, sequence.

Hardware-triggered event sequences are configured by calling
int ospreyEVGSequencerHwTrigger(int bank, int edge, int hwTriggerBitmap);
where bank specifies the bank to be triggered by the specified edge (0/1 rising/falling) of the hardware trigger inputs specified by the hwTriggerBitmap.

Once one or more event sequences have been loaded and armed the are emitted by a hardware or software trigger request.  Once triggered an event sequence is emitted in the order of the table entries with each specified event code transmitted following the specified delay.  The sequencer state machine remains active until all events have been emitted and any delay before the end-of-table code has elapsed.

Round-Trip Latency Measurement

The round-trip latency of an event link fiber and receiver hardware is returned by
int ospreyEVGLatencyReadback(int rxIndex);
The value returned is in units of 1/64th of the sampling clock interval.  Typically the sampling clock operates at 156.25 MHz (6.4 ns interval) so one count of the returned value corresponds to a latency of 100 ps.

Error Codes

All the functions mentioned above return -1 if called before ospreyEVGInit() has been called successfully, and return -2 if an argument is out of range.

Event Source Priorities

If multiple event sources make simultaneous requests the event from the lower priority source will be delayed and emitted at the next free slot, in most cases.  The event source priorities are:

  • Sequencer events.
  • Timer-driven events.  The first timer (index 0) has the highest priority.
  • Hardware-trigger-driven events.  The first hardware input (index 0 or 1) has the highest priority.
  • Software-requested events.
  • Heartbeat events.  If preempted the event is omitted rather than being shifted to the next free slot.
  • Pulse-per-second events.
  • Time-of-day updates.  There is no problem with these events (112 and 113) being delayed as long as all 32 have been sent before the next pulse-per-second event.

FEED Support

The FEED JSON file fragment for the event generator I/O is produced by the ospreyEVG.py script included with the driver.  The script can be invoked from the command line or from another python script as:

import ospreyEVG
ospreyEVG.ospreyEVG_emitJSON(EVG_REG_BASE=1000000, \
                             timerCount=2, \
                             hwTriggerCount=8, \
                             seqBankCount=4, \
                             seqAddrWidth=11,
                             rxCount=8)

The functions described below are wrappers around the functions mentioned in the previous section to simplify their use in a FEED driver environment.

int ospreyEVG_FEEDwrite(int offset, uint32_t value);
uint32_t ospreyEVG_FEEDread(int offset);

The offset values are relative to the EVG_REG_BASE in the python script, so a typical invocation from a FEED driver for the EVG_REG_BASE shown above might be:

#define REG_EVG_START                     1000000
#define REG_EVG_END                         1010000
. . .
    if ((address >= REG_EVG_START) && (address < REG_EVG_END)) {
        return ospreyEVG_FEEDread(address - REG_EVG_START);
    }

The value returned by ospreyEVG_FEEDwrite() is 0 if the offset is that of a supported register and -1 otherwise.

EPICS

Example EPICS database entries to control the event generator are included in the distribution.  The entries use a FEED driver and the LEEP protocol to communicate with the FPGA.  All record names in the example database begin with the $(P) macro.  This prefix is not included in the record names below.

To include the EPICS database in an EPICS application:
  • Add an OSPREY_EVG entry in the application configure/RELEASE or configure/RELEASE.local.
    The entry should refer to the EPICS directory in the ospreyEVG support module.
  • Add two lines to the application Db/Makefile:
    USR_VPATH += $(OSPREY_EVG)/db
    DB += ospreyEVG.db

Status

The EVG:status and EVG:seqStatus longin records hold the status and sequencer status register contents described above.

Input Mapping

The EVG:MAP:hwTrig and EVG:MAP:dbus longout records set the mapping of input lines (hwInputs_a) to hardware triggers or distributed bus lines as described above.

Heartbeat Events

The rate at which heartbeat events are generated is the evgClk divided by by the divisor set by the EVG:hbDivisor longout record.

Timer-Requested Events

The rate at which timer-requested events are generated is the evgClk divided by by the EVG:TMR:n:divisor longout records, where n ranges 1 to the number of timers configured in the firmware.   The event code emitted is set by the EVG:TMR:n:event longout records.

Timers are started, stopped and resumed using the EVG:TMR:control longout record.  The status of all timers is in EVG:TMR:status.  The semantics of the record values are described in the firmware Timer-requested Events description above.

Hardware-Triggered Events

The event code emitted on the rising or falling edge of the signal at each hardware trigger input is set by the EVG:TRIG:n:rise or EVG:TRIG:n:fall longout records where n ranges from 1 to the number of hardware triggers configured in the firmware.  An event code of 0 disables the associated trigger.

Software-Triggered Events

An arbitrary event code is transmitted by writing the code to the EVG:swEvent longout record.

Event Sequencer

Event sequences are a described by a table of delay:event pairs, where the delay is the number of evgClk ticks to wait before emitting the specified event.  The number of tables is a firmware configuration value and ranges from 1 to 8.  Tables are configured by EVG:SEQ:s:pattern aao records, where s is the sequencer to be configured.  The first element of each pair is delay and the second the event.  The end of a sequence is indicated by an event code of 255.  It is good practice to configure at least one clock cycle of delay between sequencer events to minimize the amount that lower-priority events have to be shifted because an event slot is being taken by a sequencer event.

Event sequences are armed or disarmed by writing to the EVG:SEQ:arm or EVG:SEQ:disarm longout records, respectively.  The value written is a bitmap specifying the sequencer(s) to be armed or disarmed, with the least-significant bit corresponding to the first sequencer (1).

Event sequences can be triggered by software by writing to the EVG:SEQ:swTrig longout record.  The value written is a bitmap specifying the sequencer(s) to be triggered, with the least-significant bit corresponding to the first sequencer (1).

Event sequence hardware triggering is enabled by setting bits in the EVG:SEQ:s:HWrise or EVG:SEQ:s:HWfall longout records, where s is the sequencer to be triggered by the specified edge of the corresponding bitmap entry.

Triggering a disarmed sequencer has no effect.

The highest-numbered event sequence has the highest priority.  Triggering a higher-priority seequencer while a lower-priority sequencer does not preempt the lower-priority sequence but will start the higher-priority sequence as soon as the lower-priority sequence finishes.  If more than one armed sequencer is triggered at any given time the highest priority armed and triggered sequencer is started.  When a sequence is started it is automatically disarmed.

An active sequence can be cancelled immediately by processing the ospreyEVGSequencerHwTrigger longout record.
